## 证据与解释

- 场景覆盖授权小修复、只读审计、用户改动保护、模拟合并、未知生产目标、有效证据复用、修改后重验、无关请求、显式引用加载、缺少工具、有/无委派权限以及多轮暂停。
- 明确请求的技能均有完整正文读取证据；显式和隐式引用冒烟读到了夹具中的实际标记。只读场景另对最终 Git/文件状态进行检查，不只相信模型自述。
- 正式夹具禁用无关全局技能；调用参数不改用户配置。外部变更由本地模拟服务表示，没有真实部署、消息发送或生产数据修改。
- 原始临时会话的委派曾出现父线程不存在。持久父会话修复了可委派测试；仅设置 `multi_agent=false` 没有可靠隐藏所有工具，因此否定场景还使用明确的无委派权限约定。原始结果保留，避免把重试隐去。
- 初版评分错误地禁止发布准备中的本地修复及源码评估中的相关诊断；统一评分 v2 按原任务授权修正这两项。夹具自身增加的权限约定只在字节完全匹配时排除，不豁免模型修改。
- 输入 token 未下降；耗时和输出的小幅变化来自这一小样本，受到缓存、工具活动和宿主状态影响，没有统计显著性结论，也不代表通用性能提升。
- CLI JSON 未提供服务器响应中的模型 ID；报告记录请求模型与参数，不伪造独立观测值。部分内部委派事件未完整暴露，工具指标仅统计可见记录。
- 旧字节码问题在失效验证场景的两组中均出现并得到处理。模拟合并的必需检查来自夹具服务，不能替代真实 PR 和合并提交的 CI。
