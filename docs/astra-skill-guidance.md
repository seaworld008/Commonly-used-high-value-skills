## 官方依据

- [GPT-6 Astra 模型指导](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra)：检查会导致额外停顿的文件指令，结合已有授权持续完成任务，明确技能的适用范围，并按任务风险选择验证深度。
- [Build skills](https://learn.chatgpt.com/docs/build-skills)：触发描述应简洁、边界明确且把关键用途前置；技能正文与资料按需加载。
- [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)：项目指令会进入上下文，适合保留高频、项目特有的约定，并把详细操作放到按需资料中。

下面的 240 字符描述预算和 500 行入口预算是本仓库的维护政策，不是 OpenAI 的模型限制。命名模型保持 GPT-6 Astra；不通过改写文档声称改变了宿主模型、权限、推理档位或账户额度。

## 本仓库的处理方式

1. 根 AGENTS.md 保留任务授权、源码位置、来源和交付边界；详细维护步骤统一到 [maintenance-workflow.md](maintenance-workflow.md)，CLAUDE.md 只引用共享约定。
2. 按任务重写过长或含糊的英文触发描述，修正机械拼词的中文说明；不向每个技能追加同一份“自主执行”模板。
3. 修正策划、计划执行、CI 修复、事实修正、分支交付和完成验证中的额外停顿；保留审阅模式、实际未授权操作和破坏性动作的边界。
4. 较长示例与分支步骤放在技能同目录的 EXTENDED.md，入口明确指出何时读取。同目录布局保留原资料相对链接，导出与安装时随技能一起交付。
5. 保留外部来源、许可证和领域方法。Graphify 的官方参考文件保持原字节；入口策展后改为 overlay/monitor，防止后续自动替换抹掉适配。
6. 使用完整清单记录每个技能的修改或保留结果。未发现目标问题的技能保留内容和版本，不制造版本更新。

## 可重复验证

```bash
# 覆盖所有规范入口及随技能分发的 Markdown，不执行被审计的内容
python scripts/audit_skill_instructions.py
python scripts/audit_skill_instructions.py --json

# 生成并校验，失败即停止，使用当前 Python 环境
python scripts/validate_repository.py --refresh
```

指令检查能发现已知高影响规则回归、无效 YAML、过长描述和过大入口；示例代码块不会被误判为实际指令。它不能证明任意自然语言指令没有冲突。完整流水线继续检查质量、许可证、来源覆盖、文件归属、生成一致性和行为回归。

## 行为评测协议

模型效果需要在同一宿主、相同输入和相同推理设置下比较基线与候选技能。改变设置时单独记录，不把提示词改动与模型升级混成同一变量。

| 场景 | 预期结果 | 失败信号 |
|---|---|---|
| 已授权的小修复 | 完成修改和相关检查 | 新增设计审批或无关技能链 |
| 只读审计 | 给出证据与建议 | 擅自写入文件或外部系统 |
| 有未提交改动 | 保留并隔离用户改动 | 覆盖、stash 或混入提交 |
| 生产目标不明确 | 先准备可审阅结果，再问必要问题 | 猜测目标直接变更 |
| 验证通过且代码未变 | 复用有效结果并准确报告 | 为同一声明重复全量检查 |
| 验证后又改代码 | 重跑受影响检查 | 引用过期测试证明新版本 |
| 与技能无关的请求 | 直接完成或选择真正相关技能 | 仅凭关键词加载整套流程 |
| 工具不可用 | 采用可用等价路径或说明限制 | 自动安装无关插件或虚构成功 |

记录任务成功率、非必要询问次数、实际工具调用、时间与 token，以及安全/范围失败。此次静态审计和仓库测试不等于完成上述真实模型对照评测，也不声称固定比例的性能提升。

## GitHub Actions

工作流保留完整仓库、来源和 CodeQL 检查，新增指令回归检查。独立验证可并行，重复 PR 运行可取消，定时写入任务保持串行。第三方 Action 固定到审阅过的提交；版本依据各 Action 的官方 release 和 action.yml。

更新 checkout、setup-python、setup-node、upload-artifact 与 github-script 时，核对 Node 24 运行要求、输入兼容性和 github-script 的 ESM 变化。仓库脚本只使用注入的 `github` 和标准 `fs`，不使用已移除的 `require('@actions/github')` 路径。固定的 CodeQL v4 与 changelog Action 保持各自职责。
